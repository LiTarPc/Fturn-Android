**Прикладные ответы сайтов:** без обхода RU Почта России возвращала HTTP 417 на обоих протоколах, а в TCP-проверке с ПК `m.vk.com` завершался таймаутом. После включения обхода сайты на телефоне вернули HTTP 200, а все 11 TCP-проверок с ПК прошли. В тестовом клиенте RU-проверка означает доступность TLS/HTTP-транспорта и сохраняет код ответа; её положительный флаг при HTTP 417 не означает успешное открытие страницы. Этот результат вынесен отдельно, а не скрыт в общем числе прошедших проверок. Вход в аккаунты не выполнялся.

Успешный импорт сам по себе не считается успешным VPN-подключением. После получения актуальной RAW-ссылки проверены запуск VPN и передача данных. Ранее сохранённый профиль этого же сервера имел MTU 1420; актуальный — 1350. Контрольная замена только MTU на 1420 снова дала тайм-аут 180 секунд; возврат 1350 дважды восстановил соединение. В RAW-сервере есть точная проверка MTU по provisioning (`third_party/raw-core/internal/rawvpn/server.go:160`). Серверный лог не читался, но сравнение на одном телефоне и проверка исходников указывают на несовпадение MTU. Для второго старого RAW-сервера (`RAW-alt`) результат остаётся неподтверждённым.

## Дополнительная проверка новой RAW-ссылки

Ссылка `fturnraw://` v4 импортирована реальным парсером: UDP, rtpopus2, uplink tcp-flow, MTU 1350, 21 поток, 7 потоков на credential. Ключи, адрес сервера и ссылка звонка в отчёт не включены.

Два полных подключения заняли 21,6 и 15,8 секунды, с выключенным и включённым RU-обходом. TUN прошёл по 15/15 проверок: HTTPS, IPv4, DNS TCP/UDP, перехват DNS к тестовому адресу, подавление AAAA, STUN UDP и параллельные запросы. SOCKS5 на телефоне прошёл 17/18 и 18/18: в первом цикле один параллельный HTTPS-запрос завершился тайм-аутом. Через USB TCP-forward прошли по 12/12 проверок.

Отдельно проверена раздача SOCKS5 с телефона по Wi-Fi на ПК: TCP CONNECT, UDP ASSOCIATE, DNS, STUN, обязательный пароль, отказ при неверном пароле, закрытие UDP после закрытия TCP control, IPv6 literal reject и параллельные HTTPS. Первый согласованный прогон: 17/18 (тайм-аут STUN); повторный полный прогон: 18/18. Два ранних несогласованных запуска, попавших на остановку VPN, не учитываются в результатах. Единичные тайм-ауты сохранены как предупреждения, а не скрыты успешным повтором.

Во всех успешных RAW-циклах росли RX/TX, оставалось одно VPN-уведомление, соединение сохранялось в фоне и полностью останавливалось. Без RU-обхода Pochta.ru вернула HTTP 417; с обходом Yandex, Pochta и VK вернули HTTP 200. Проверка DNS не заменяет отдельный аудит браузерного DoH/DoT. После проверки восстановлены исходные настройки отдельной тестовой сборки и удалены временные входные файлы и USB-forward. Производственный код и APK не менялись.

## Методика и ограничения

Реальные подключения запускаются обычным `LocalProxyManager` / `ProxyService`, с профилями из истории пользователя и ранее сохранённых настроек. Приватные ключи и ссылки не включены в APK или этот отчёт.

TUN проверялся отдельным нативным процессом от shell UID: исключение UID самого VPN-приложения не позволяет ему обойти тест. SOCKS5 проверялся отдельно на телефоне, через USB TCP-forward и по Wi-Fi LAN с компьютера. Для внешних сервисов использовались публичные HTTPS-страницы, DNS и STUN. Проверка не выполняет вход в пользовательские аккаунты.

Внешние адреса в исходной сети и через VPN совпадают для зарубежного IP-сервиса; Яндекс также не дал однозначного изменения при переключении. Поэтому по ним не объявляется доказанным прямой маршрут. Дополнительный контроль использует случайный ответ временного HTTP-сервера на ПК и USB reverse. Loopback не входит в Android TUN: эта проверка подтверждает работу общей таблицы правил через SOCKS5, а не является отдельным TUN-тестом обхода.

При первой передаче SRS через stdin ADB файл обрезался до 16 байт. После бинарной передачи через `adb push` и проверки точного совпадения 8275 байт импорт прошёл. Это была ошибка подготовки теста; производственный обработчик SRS не менялся.

Проверка порта 53 не является полным аудитом DoH/DoT, браузерных Secure DNS или всех сценариев утечек. Длительный прогон, смена Wi-Fi/мобильной сети и серверные SSH-функции в эту сетевую проверку не входили. Обновления серверов и публикация релиза не выполнялись.
