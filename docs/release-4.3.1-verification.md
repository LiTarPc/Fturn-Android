## Живые проверки установленного APK

Устройство: Honor TFY-LX1, Android 13 / API 33, USB ADB. Использован существующий RAW-профиль: транспорт TURN TCP, передача RAW по пакетам, MTU 1350, включён нативный RU-обход. Исходные профили не удалялись, пользовательские правила и пароль раздачи не менялись. Дополнительные изменения проверялись на временной копии профиля, удалённой после тестов.

1. RAW подключился к пользовательскому серверу. HTTPS вернул `200`, внешний адрес совпал с RAW-сервером; TCP- и UDP-DNS вернули корректные ответы. Ошибка `file already closed` на финальном APK не повторилась в выполненных запусках.
2. Под нагрузкой установлены **320 из 320 реальных TLS-соединений** к внешнему HTTPS-узлу, без ошибок; время установления около 3,6 с. Все соединения удерживались открытыми до контрольного HTTPS-запроса. Новый HTTPS-запрос вернул `200` во время нагрузки и после освобождения соединений. PID приложения и RAW во время проверки не изменились. Это проверка одновременных соединений, а не скорости передачи данных.
3. Старый локальный SOCKS-мост не слушает порт и не участвует в передаче обычного трафика телефона. Основной путь: Android TUN → RAW. Остался отдельный аутентифицированный HTTP CONNECT на loopback для явных служебных запросов.
4. Нативный RU-обход проверен внешним HTTPS-запросом к адресу Яндекса, совпадающему с встроенным RU CIDR-списком. При активном RAW ресурс увидел тот же внешний адрес, что и после штатного отключения VPN; этот адрес отличается от RAW-сервера. Сравнивались хеши адреса, без публикации пользовательского IP. После восстановления RAW обычный HTTPS снова вышел через сервер, оба DNS-транспорта прошли.
5. Штатная остановка убрала нативный процесс. Отмена примерно через 300 мс после начала подключения также не оставила процессов ядра. Следующий запуск создал ровно одно ядро и снова прошёл HTTPS, TCP-DNS и UDP-DNS.
6. У установленного APK служебный HTTP CONNECT отверг запрос без авторизации ответом `407`. Слушатель доступен только на loopback.

## Проверки нативных адаптеров и обработчиков

- На физическом Android прошли тесты передачи TUN-дескриптора с подтверждением, проверки несовпадающего канала, закрытия до подключения TUN и протокола защиты сетевых дескрипторов.
- На Android прошли 14 тестов нативного обхода: TCP half-close, UDP, повторное использование портов, CIDR/RU, DNS, SRS, логические условия, доменные правила, сетевые протоколы, порты и срок жизни DNS-привязки.
- Четыре JVM-теста `RawProxyServerTest` прошли на хосте и в отдельном DEX на Android/ART: HTTP без авторизации; авторизованный HTTP с ответом после завершения загрузки; отказ SOCKS без нужного метода/с неверным паролем; SOCKS UDP после повреждённого пакета с закрытием управляющего соединения. Для Android тестовые loopback-узлы явно привязаны к IPv4 `127.0.0.1`, поскольку системный `getLoopbackAddress()` может вернуть `::1`. Производственный исходник обработчика не менялся.
- Дополнительно отдельный процесс с тем же исходником Android-обработчиков запущен на телефоне при активном установленном RAW VPN. Использованы временные случайные учётные данные и loopback-порты; пользовательские настройки не менялись. Проверены отказ неверного пароля SOCKS, внешний HTTPS через SOCKS с адресом RAW-сервера, SOCKS UDP-DNS, авторизованный HTTP CONNECT с внешним HTTPS через RAW, GitHub latest API (`200`) и скачивание RU-списка (`200`, 8664 корректных IPv4 CIDR). После тестов временные обработчики остановлены.

## Дополнительные проверки после разблокировки телефона

- Экран «О приложении» показывает `v4.3.1`; ручная проверка обновлений через работающий RAW завершилась сообщением «Установлена последняя версия».
- В обеих вкладках параметров подключения проверена вертикальная прокрутка: доступны нижний раздел DNS в «Транспорт TURN» и настройки RAW с переходом VPN в «Прокси и VPN».
- При активном исходном RAW создана неактивная временная копия профиля. В её настройках успешно выполнена команда «Загрузить / обновить RU IPv4»: приложение подтвердило сохранение списка. Загрузка прошла через служебный HTTP CONNECT работающего VPN. Исходный профиль сохранил прежние правила.
- На копии включён режим «Только выбранные» с одним установленным приложением. После переключения на неё установленный APK запустил RAW и SOCKS-раздачу с существующими пользовательскими учётными данными. SOCKS отверг неверный пароль, HTTPS через SOCKS вернул `200` с адресом RAW-сервера, UDP-DNS прошёл. Непомеченный процесс ADB при этом выходил напрямую, а исходящие соединения SOCKS-прокси приложения — через RAW: собственный UID приложения корректно добавлен к VPN в режиме INCLUDE.
- Существующий профиль `adminNetherLand` с TURN/WireGuard подключился на том же APK. Обычный HTTPS вернул `200` с адресом его сервера, TCP-DNS и UDP-DNS прошли. Дополнительно прошли авторизация SOCKS, HTTPS через SOCKS с адресом этого сервера и SOCKS UDP-DNS. RAW-процесс при переходе остановлен, запущено только TURN-ядро.
- После штатной остановки не осталось нативных процессов и слушателя раздачи на порту 1080. Исходные порт и пароль раздачи сравнены с сохранёнными перед тестом и совпали. Раздача возвращена в исходное выключенное состояние; временная копия удалена. Снова выбран исходный RAW с прежним режимом «Все, кроме выбранных» и включённым прежним RU-списком. Повторно пройдены HTTPS через RAW, TCP-DNS и UDP-DNS; порт раздачи закрыт.

Перед переключением профилей исходная RAW-сессия достигла **40 минут 18 секунд** с тем же PID ядра. В заключительном интервале от 27:53 до 40:18 выполнены 24 регулярных замера, каждый с HTTPS и TCP/UDP DNS: все прошли. Более ранние живые проверки этой сессии также были успешны. Это наблюдение одной сессии с небольшими периодическими запросами, а не непрерывная нагрузка на максимальную скорость.

## Границы проверки

Подтверждённый ранее предел 256 соединений старого моста устранён из основного пути RAW и превышен в живом тесте. Исходный длительный сбой после десятков минут работы не доказан как следствие только этого предела. В наблюдавшейся сессии продолжительностью более 40 минут он не повторился; нагрузка и наблюдение одной сессии не заменяют длительную эксплуатацию в разных сетях.

После разблокировки выполнены описанные выше проверки интерфейса, обновления RU-списка, проверки доступной версии приложения, второго профиля и пользовательской SOCKS-раздачи установленного APK. Загрузка и установка следующей версии через встроенный updater не выполнялись, поскольку опубликованная и установленная версии совпадают. Подключение второго устройства к раздаче по LAN/Wi-Fi, смена Wi-Fi/мобильной сети и живое VLESS-подключение не выполнялись. Устройство использовало мобильную сеть; доступного Wi-Fi-интерфейса для LAN-проверки не было.

RAW остаётся IPv4. DNS идёт через RAW. Доменные SRS-правила получают привязки из обычных DNS-ответов внутри туннеля; внешние зашифрованные DNS-запросы таких привязок не дают. Неподдерживаемые метаданные SRS отклоняются явно. Обозначения test/beta встроенных ядер сохранены.
