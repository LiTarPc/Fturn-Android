## Живые проверки установленного APK

Устройство: Honor TFY-LX1, Android 13 / API 33, USB ADB. Использован существующий RAW-профиль: транспорт TURN TCP, передача RAW по пакетам, MTU 1350, включён нативный RU-обход. Профили не удалялись, пользовательские правила и пароль раздачи не менялись.

1. RAW подключился к пользовательскому серверу. HTTPS вернул `200`, внешний адрес совпал с RAW-сервером; TCP- и UDP-DNS вернули корректные ответы. Ошибка `file already closed` на финальном APK не повторилась в выполненных запусках.
2. Под нагрузкой установлены **320 из 320 реальных TLS-соединений** к внешнему HTTPS-узлу, без ошибок; время установления около 3,6 с. Все соединения удерживались открытыми до контрольного HTTPS-запроса. Новый HTTPS-запрос вернул `200` во время нагрузки и после освобождения соединений. PID приложения и RAW во время проверки не изменились. Это проверка одновременных соединений, а не скорости передачи данных.
3. Старый локальный SOCKS-мост не слушает порт и не участвует в передаче обычного трафика телефона. Основной путь: Android TUN → RAW. Остался отдельный аутентифицированный HTTP CONNECT на loopback для явных служебных запросов.
4. Нативный RU-обход проверен внешним HTTPS-запросом к адресу Яндекса, совпадающему с встроенным RU CIDR-списком. При активном RAW ресурс увидел тот же внешний адрес, что и после штатного отключения VPN; этот адрес отличается от RAW-сервера. Сравнивались хеши адреса, без публикации пользовательского IP. После восстановления RAW обычный HTTPS снова вышел через сервер, оба DNS-транспорта прошли.
5. Штатная остановка убрала нативный процесс. Отмена примерно через 300 мс после начала подключения также не оставила процессов ядра. Следующий запуск создал ровно одно ядро и снова прошёл HTTPS, TCP-DNS и UDP-DNS.
6. У установленного APK служебный HTTP CONNECT отверг запрос без авторизации ответом `407`. Слушатель доступен только на loopback.

## Проверки нативных адаптеров и обработчиков

- На физическом Android прошли тесты передачи TUN-дескриптора с подтверждением, проверки несовпадающего канала, закрытия до подключения TUN и протокола защиты сетевых дескрипторов.
- На Android прошли 14 тестов нативного обхода: TCP half-close, UDP, повторное использование портов, CIDR/RU, DNS, SRS, логические условия, доменные правила, сетевые протоколы, порты и срок жизни DNS-привязки.
- Четыре JVM-теста `RawProxyServerTest` прошли на хосте и в отдельном DEX на Android/ART: HTTP без авторизации; авторизованный HTTP с ответом после завершения загрузки; отказ SOCKS без нужного метода/с неверным паролем; SOCKS UDP после повреждённого пакета с закрытием управляющего соединения. Для Android тестовые loopback-узлы явно привязаны к IPv4 `127.0.0.1`, поскольку системный `getLoopbackAddress()` может вернуть `::1`. Производственный исходник обработчика не менялся.
- Дополнительно отдельный процесс с тем же исходником Android-обработчиков запущен на телефоне при активном установленном RAW VPN. Использованы временные случайные учётные данные и loopback-порты; пользовательские настройки не менялись. Проверены отказ неверного пароля SOCKS, внешний HTTPS через SOCKS с адресом RAW-сервера, SOCKS UDP-DNS, авторизованный HTTP CONNECT с внешним HTTPS через RAW, GitHub latest API (`200`) и скачивание RU-списка (`200`, 8664 корректных IPv4 CIDR). После тестов временные обработчики остановлены.

## Границы проверки

Подтверждённый ранее предел 256 соединений старого моста устранён из основного пути RAW и превышен в живом тесте. Исходный длительный сбой после десятков минут работы не доказан как следствие только этого предела; короткий нагрузочный тест не заменяет длительную эксплуатацию.

Телефон во время заключительных проверок был заблокирован. На финальном APK не проверялись через интерфейс обновление списков/приложения, переключение второго профиля и включение пользовательской SOCKS-раздачи. Их транспортные обработчики проверены отдельно на Android, как описано выше. Подключение второго устройства к раздаче по LAN/Wi-Fi, смена Wi-Fi/мобильной сети и живое VLESS-подключение не выполнялись. Устройство использовало мобильную сеть; доступного Wi-Fi-интерфейса для LAN-проверки не было.

RAW остаётся IPv4. DNS идёт через RAW. Доменные SRS-правила получают привязки из обычных DNS-ответов внутри туннеля; внешние зашифрованные DNS-запросы таких привязок не дают. Неподдерживаемые метаданные SRS отклоняются явно. Обозначения test/beta встроенных ядер сохранены.
