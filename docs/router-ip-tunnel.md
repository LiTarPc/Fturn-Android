# Устройство IP-туннеля роутера

Руководство пользователя: [подключение OpenWrt через USB](router-ip-auto.md). Ниже — описание реализации 4.3.9 для разработчика.

## Путь данных

```text
LAN → Linux IPIP/FOU на роутере → UDP → fturn-fou на телефоне
    → пользовательский сетевой стек → маршрут/DNS/VPN Fturn → удалённый сервер
```

Ответы возвращаются через тот же приёмник к роутеру. Android VPN TUN не используется для внедрения чужих исходящих пакетов. Для внешних клиентов создаётся отдельный стек gVisor; соединения обрабатываются общим движком Fturn.

## Два режима

- **Автоматический:** HTTP-привязка по общему коду определяет адреса и ограничивает текущего peer. Готовый OpenWrt-помощник использует USB.
- **Ручной:** пользователь задаёт частные IPv4 телефона и роутера. После смены адресов их нужно обновить и переподключить VPN.

В автоматическом режиме одновременно обслуживается один привязанный роутер. При этом за ним может быть несколько обычных LAN-клиентов. Поддержка нескольких независимых туннельных отправителей не реализована.

## Управление и порты

По умолчанию данные идут по UDP `40080`, управление — TCP `40081`. Роутер посылает `POST /v1/lease` с Bearer-кодом, состоящим из 32 случайных байт в шестнадцатеричном виде. Допускаются только частные IPv4 и согласованный peer; адреса берутся из соединения.

Ответ содержит версию протокола, адреса, UDP-порты, MTU, допустимые исходные подсети и срок привязки. Продление выполняется приблизительно каждые три секунды; срок — 12 секунд. Неверный код отклоняется, другая сторона не может заменить живую привязку до её истечения.

## Данные

Используется Linux FOU с `ipproto 4`: UDP переносит IPv4-пакеты. Это не SOCKS5 и не переадресация на порт 1080.

Приёмник проверяет внешний peer, допустимую исходную подсеть, IPv4-версию, длину заголовка/пакета, TTL и checksum. Внутренние фрагменты передаются сетевому стеку. MTU по умолчанию 1350, допустимо 576–1400. Объём очередей ограничен; UDP NAT допускает до 4096 потоков.

Локальный FOU не шифрует пакеты. В автоматическом режиме код разрешает установление привязки, но не заменяет шифрование канала. Предназначение — отдельное доверенное USB-соединение. IPv6 через этот вход не реализован.

## Роутер

Помощник получает адреса из `fturn-hotspot-upstream`, создаёт `ftfouauto` и таблицу `40081`. Он проверяет прохождение DNS до добавления общего LAN-правила. Текущая сеть LAN должна совпадать с разрешённой подсетью приложения.

При ошибке помощник удаляет свои ресурсы и возвращает прежнюю политику роутера. Он не настраивает резерв HEV, dnsmasq или блокировку обычного WAN автоматически.

Готовый адресный помощник ожидает `usbwan` и `usb0`; основной контроллер ожидает `br-lan` и fw4/nftables. Смена интерфейса на Wi-Fi требует отдельной адаптации роутерной части. Приём данных по локальному Wi-Fi технически проверен, но универсального Wi-Fi-установщика нет.

## Исходники и проверки

- Приёмник и его тесты: `scripts/patches/fou`.
- Применение к закреплённому sing-box: `scripts/patch-fou.py`.
- Проверка готовой AAR: `scripts/verify-libbox.py`.
- Контроллер OpenWrt: `scripts/router/fturn-fou-auto.sh` и сервис `.init`.
- Определение адресов: `scripts/router/fturn-hotspot-upstream`.
- Сквозная сетевая проба: `scripts/tests/fou_client_probe.go`.

Нативные тесты проверяют ручной/автоматический TCP и UDP, отказ посторонним узлам, истечение привязки, смену адресов, валидацию пакетов и освобождение ресурсов. Сквозная проба проверяет UDP DNS, TCP DNS и HTTPS от двух независимых клиентов.

Фактическая приёмка и её ограничения находятся в [отчёте 4.3.9](release-4.3.9-verification.md). Первые замеры и ручные прототипы сохранены в [архиве](archive/router-ip-tunnel-prototype-2026-11-12.md).
