# Fturn 4.3.4 - persistent diagnostic journal

Adds an application-private rolling journal capped at 50 MiB (ten 5 MiB segments).
It records the existing core, sing-box and connection-event log stream on an IO
worker, with timestamps and application/profile session markers. Reconnection
still clears the short on-screen list, while disk history survives reconnection
and process restarts. Explicit Clear journal removes both histories.

Logs > Export journal saves a ZIP through Android's document picker. The archive
contains events.log and diagnostic-info.txt. Known profile/hotspot credentials,
authorization fields, profile links and URL queries are redacted independently of
the UI privacy setting. Export stays local until the user chooses a destination.
The bounded writer queue reports overload drops; disk errors are shown on screen.
The collector follows the existing logging setting and does not capture OS logcat.

RAW stays 1.0.1-beta.android.3, with the same sing-box -> RAW path, TCP DNS and
1024-handler limit. This build adds diagnostics; it does not claim to fix the
intermittent Internet failures. Native reconnect corrections are tested separately.

Local JVM regression checks cover rotation with more than 50 MiB of UTF-8 input,
restart retention, explicit clear, ordered export, credential redaction and
initialization failure. Signed CI and device verification are recorded separately.
