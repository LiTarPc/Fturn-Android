# Fturn 4.3.5 - RAW reconnect candidate and support access

Updates RAW from 1.0.1-beta.android.3 to 1.0.1-beta.android.3-reconnect.1.
Two reproduced client defects are corrected: TURN allocation pacing now happens
after credentials become available, and cached valid credentials remain usable
when another group has an authorization cooldown. The pinned snapshot changes
only client.go, reconnect regression tests and the default core version.

The candidate's rawvpn suite passed on Honor/ART in standalone loopback tests
(49 pass, one optional test skipped), including repeated TCP worker resets in
packet/tcp-flow mode and a silent UDP blackhole. A local rebuild from the pinned
source matches the candidate binary byte-for-byte:
23c988dd3b40e29c823d63ad85a43591ba5ba699bcd5c8050999d8c5f61d1194.
The app keeps sing-box -> RAW, TCP DNS and the 1024-handler bridge limit.
These tests reproduce the two defects but do not establish that every reported
live Internet stall has the same cause.

Ordinary Settings now includes Save journal and Send logs to support. The latter
opens https://t.me/FturnSupport; the user attaches the saved ZIP in Telegram and
confirms sending there. Debug mode is not required to access these actions.
Export uses the same document picker as the developer Logs screen.

Opaque captcha request/proof bodies are removed from new log entries and from
exports of older history. Status and timing lines remain. Clearing the journal
also removes the application's private temporary ZIP, while files deliberately
saved by the user remain in the selected folder.
