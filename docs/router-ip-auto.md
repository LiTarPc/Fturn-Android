# Автоматический IP-туннель Fturn для OpenWrt

Режим подготовлен для Fturn 4.3.9 и доступен в настройках VPN. До завершения проверки обновления он также доступен в отдельной сборке «Fturn IP-туннель TEST». На Android root не нужен. На роутере один раз устанавливаются совместимые модули FOU/IPIP, `ip-full`, `coreutils-timeout` и помощник из `scripts/router`.

## Подключение подготовленного телефона

1. В Fturn выбрать рабочий VPN-профиль.
2. Открыть Настройки → VPN → IP-туннель роутера, включить «Автоматическая привязка» и указать код этого роутера. На уже подготовленном Honor код сохранён.
3. Включить IP-туннель, сохранить настройки и переподключить VPN.
4. Подключить телефон к USB роутера и включить USB-модем в настройках Android.

Ручной ввод IP-адресов не нужен. При появлении USB-сети помощник получает адреса из текущей DHCP-конфигурации OpenWrt и соединяется с Fturn. Данные проходят через действующий VPN-профиль. MTU по умолчанию 1350; дополнительные поля обычно менять не требуется.

Для другого телефона один раз установить ту же сборку, добавить VPN-профиль и указать **тот же код привязки**. Код можно скопировать в настройках уже привязанного Fturn. Создание нового кода на одном телефоне не меняет код на роутере.

SOCKS5-раздача не требуется для основного FOU-пути. Она нужна, если используется прежний резервный маршрут HEV. При выключенной SOCKS5-раздаче возврат роутера к HEV не сможет восстановить интернет. Без работающего VPN Fturn закрывает и FOU-приёмник.

## Как устроено обнаружение

Помощник роутера обращается к телефону по TCP 40081 и предъявляет случайный 256-битный код. Fturn берёт адрес роутера из принятого соединения, адрес телефона — из его локального endpoint; заранее сохранённые адреса не используются. На телефоне одновременно разрешён один привязанный роутер. Привязка обновляется примерно каждые три секунды и истекает через 12 секунд без обновления. Данные IPv4 передаются отдельно по UDP 40080, совместимо с Linux FOU.

Роутер согласует порты и MTU с телефоном и проверяет, что разрешена его LAN-подсеть. До переключения LAN выполняется настоящий DNS-запрос через FOU. При потере USB, отказе привязки или ошибке проверки помощник удаляет свои маршруты и сохраняет прежнюю политику HEV. Сам HEV и его конфигурация не изменяются.

Код привязки и внутренние IP-пакеты передаются в выделенной USB-сети без шифрования. Этот протокол предназначен для непосредственного USB-соединения с доверенным устройством. Код хранится в приватных настройках Android и в `/etc/fturn-fou-auto.key` на роутере с правами 600; в APK и исходниках рабочего кода нет.

## Файлы и обслуживание OpenWrt

- `/usr/sbin/fturn-fou-auto`: помощник `scripts/router/fturn-fou-auto.sh`.
- `/etc/init.d/fturn-fou-auto`: procd-сервис `scripts/router/fturn-fou-auto.init`.
- `/etc/fturn-fou-auto.key`: 64 шестнадцатеричных символа кода, права 600.
- `/var/run/fturn-fou-auto.state`: текущее состояние; это промежуточный файл, наличие которого само по себе ещё не означает готовый маршрут.
- `ftfouauto`, policy table 40081, priorities 1076–1078: ресурсы автоматического туннеля.

Текущая реализация рассчитана на существующую конфигурацию этого Omni: USB-интерфейс `usb0` / сеть `usbwan`, LAN `br-lan`, помощник определения upstream `/usr/sbin/fturn-hotspot-upstream`, firewall fw4/nftables. На другом роутере названия сетей и существующую политику необходимо сверить до установки. Модули должны точно соответствовать версии и ABI ядра; принудительно обходить проверку зависимости kernel нельзя.

Проверка статуса и журнала:

```sh
/etc/init.d/fturn-fou-auto enabled
ubus call service list '{"name":"fturn-fou-auto"}'
cat /var/run/fturn-fou-auto.state
ip rule
logread -e fturn-fou-auto
```

Остановить автотуннель и вернуть прежний маршрут HEV:

```sh
/etc/init.d/fturn-fou-auto stop
```

Отключить автозапуск:

```sh
/etc/init.d/fturn-fou-auto disable
```

Включить снова:

```sh
/etc/init.d/fturn-fou-auto enable
/etc/init.d/fturn-fou-auto start
```

Код не нужно менять при смене IP, порта USB или переподключении того же телефона. После изменения кода или параметров в приложении требуется переподключить VPN. После восстановления резервной копии IP-туннель остаётся выключенным до явного включения пользователем.

## Проверенные результаты

На Honor X8 / TFY-LX1 без сохранённых адресов прошли DNS UDP, DNS TCP и HTTPS для двух независимых внутренних адресов: 6/6. Неверный код отклонён. На физическом USB Omni повторно прошли DNS UDP/TCP и HTTPS, включая общий LAN policy route. Проверено удаление маршрутов при неверном коде и автоматическое восстановление после возврата правильного кода.

Нативные тесты ручного и автоматического TCP/UDP, истечения привязки, смены адресов и отказа неверному коду прошли в 20 повторах. Пройдены JVM-тесты и Android lint. Постоянный procd-сервис установлен и включён в автозапуск на Omni. После остановки сервиса его маршрут удаляется, после запуска восстанавливается. Проверен логический цикл `ifdown usbwan` / `ifup usbwan`: FOU останавливается и восстанавливается после получения DHCP без ручного ввода адресов. После удаления временных инструментов повторно прошли DNS UDP/TCP и HTTPS через установленные файлы.

Во flash после установки осталось 468 КиБ. После очистки временных пакетов MemAvailable составил около 9 МиБ. Конфигурация HEV сохранена. Рабочий код привязки не оставлен во временных файлах компьютера или роутера.

Это экспериментальная функция. Длительная устойчивость, CS2 и перезагрузка всего роутера отдельно не подтверждены. Функция не публиковалась в стабильном релизе.
